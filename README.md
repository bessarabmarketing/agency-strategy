# Agency Strategy OS

Внутрішній інструмент агенції: конструктор маркетингових і SMM-стратегій.
**Один проєкт → одна стратегічна база → одна логіка бренду → багато каналів.**

## Запуск
Потрібен Node.js ≥ 22.13 (зовнішніх залежностей немає, `npm install` не потрібен).

```bash
cp .env.example .env      # заповніть ANTHROPIC_API_KEY (+ APIFY_TOKEN для парсингу, TEAM_KEY для захисту)
export $(grep -v '^#' .env | xargs) && node server.js
# відкрийте http://localhost:3000
```
Docker: `docker build -t aso . && docker run -p 3000:3000 -v aso-data:/data --env-file .env aso`

## Склад
- `index.html` — увесь фронтенд в одному файлі (без збірки). Усередині блок `CFG` — **методологія агенції**: послуги, правила Service→Module, модулі та їхні секції, залежності, агенти, бриф.
- `server.js` — спільна БД (SQLite), проксі до Claude API з web search, парсинг (Apify), фонові задачі. Ключі лишаються на сервері.
- `dev/mock.js`, `dev/e2e.py` — мок Claude/Apify і наскрізний тест (Playwright). **Лише для розробки.**

## Як змінити методологію / додати послугу без переписування коду
1. `CFG.SERVICES` — додати послугу (id, група, канал).
2. `CFG.MODULES` — описати модулі (секції-поля, залежності `deps.hard/soft`, роль AI).
3. `CFG.RULES` — правило `when → enable` (і за потреби `sections` для розширення існуючих модулів).
4. У розділі **AI Agents** можна без коду додавати інструкції агенції до кожного агента; у **Бібліотеці** — правила, шаблони, кейси (вони автоматично додаються до контексту AI).

## Як працюють гарантії проти вигадок AI
- Модуль запускається, лише якщо його жорсткі залежності **зафіксовані** (Project Context).
- Кожне твердження має тип: дані клієнта / зовнішнє дослідження / AI-висновок / AI-гіпотеза. «Зовнішнє дослідження» без URL автоматично понижується до гіпотези.
- Конкуренти поза брифом відкидаються; аватари без існуючого сегмента підсвічуються; загальні фрази й цифри без джерела дають попередження.
- Зміна критичних полів брифу, залежностей, складу каналів або дат парсингу позначає модулі як `↻ Потрібно оновити` (з причиною).

## Парсинг
Через Apify (`APIFY_TOKEN`). Збираються лише публічні дані. Формат відповідей акторів Apify змінюється — після підключення токена перевірте по одному акаунту кожної платформи; нормалізація в `server.js` (`normalize`) толерантна до відсутніх полів. Актори змінюються через `APIFY_ACTOR_*`.

## Командна робота
Спільна БД, історія версій (знімки на ключових подіях), виявлення конфліктів версій (два PM правлять один проєкт). Авторизація — простий спільний `TEAM_KEY` + імʼя користувача; повноцінні акаунти й ролі — Phase 2.

## Phase 2
Прямі інтеграції експорту (Google Docs API, Notion API), повноцінна авторизація та ролі, векторний пошук по Knowledge Base, потокова передача відповідей AI, редактор Strategy Map, черга задач у зовнішньому сховищі (зараз задачі в памʼяті сервера).
